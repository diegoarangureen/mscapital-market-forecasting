# EXP-GRU-003：序列与窗口特征内部融合 / 严格折外表征方案
日期：2026-09-12
状态：设计已落盘，尚未实现或运行训练。先完成EXP-EVAL-001，再按本方案推进；不继续微调EXP-GRU-002纯GRU。

## 要回答的问题

窗口统计描述“一段时间总体怎样”，GRU描述“事件怎样依次发生”。本实验先让两类信息在网络内部一起影响预测，检查序列分支是否提供静态窗口特征之外的增量。通过筛选后，才检查冻结表征能否帮助树模型。

论坛CV/PB数字作为用户提供的研究线索保留，不视为本地可复现证据：GRU1 0.1766/0.143、GRU2 0.1689/0.140、GRU+Tree 0.1626/0.142、融合0.1789/0.147（10 seeds）。尚未核验帖子切分、特征、预处理或实现，不据此承诺收益。

多泛化面板用于筛选，不意味着要改损失函数。本实验保持训练期全局目标标准化后的MSE。

## 先解决输入边界

复用319个无目标窗口特征的构建定义。sample_id只对齐，month只划分；禁止目标列和目标派生特征进入输入。

现有sequence_cache_v1的前11通道先按0–59统计标准化、再存float16。已查证transaction_avgprice统计的training_sample_count=1,064,163，缓存构建脚本采用训练期均值/标准差。EXP-GRU-002随后按折重新标准化缓存，并反变换构造派生通道。

对于更早的训练折，原缓存的数值编码已依赖后续月份的无标签统计。理想实数下仿射变换可以抵消，但float16量化不可精确撤销。因此新实验若声称预处理严格仅fit训练折，不能直接把旧float16缓存反变换后当原始数据。这里没有发现目标泄漏证据，也不据此量化旧结果偏差。

实现前要求：
- 从原始market按既定sample_id、时间顺序、最近200条、左padding/右对齐规则，分列或分批写**未用全局统计变换的float32原值缓存**。
- 只保留样本自身决定的缺失mask与确定性时间变换。原值的缺失处理不能调用全样本均值/中位数。
- 14×200×1,257,637×4约14.09GB（13.12GiB），使用磁盘映射，不整块载入内存；创建前核对实际剩余磁盘。
- 每一训练折只在自己的有效事件上fit连续通道均值/标准差；valid、embedding折与外部验证只transform。派生通道先用当前样本原值计算。
- 表格中位数、Quantile结点和目标均值/标准差也只fit对应训练段。
- 如未来选择折内重建标准化缓存代替原值缓存，必须在训练前更新实现记录并保持上述边界，不能悄悄复用旧量化路径。
- 无新依赖安装；实现时核对本机PyTorch接口，避免凭记忆改已有环境。

GRU必须避免左padding推进隐藏状态：把有效事件移至前部并按长度打包，或用等价显式mask的递归计算。不能只把padding输入置零，因为GRU偏置仍可能更新隐藏状态。验证时必须检查同一有效序列仅改变padding数量，表征/预测不变。这里是正确性验收，不是训练smoke test。

## 第一阶段：单seed、双窗口、内部融合

固定seed42；两折依次运行：
- A：训练0–49，验证50–59。
- B：训练0–59，验证60–70，同时评分62–70去66（中间隔60、61两个月）与67–70。
- 固定预算2 epochs，MSE、AdamW，learning_rate=0.001，weight_decay=0.0001，梯度裁剪1.0，dropout=0.10，batch512、推理batch1024；不按验证月选epoch。
- 原始200事件、14原通道+既有8个样本内派生通道；单层GRU hidden64。
- 静态分支：训练折Quantile预处理后的319特征及训练折确定的缺失标记 → Linear128 → SiLU → Linear64 → SiLU。
- 序列分支：逐事件投影64 → GRU64 → 最后有效隐藏状态64。
- 拼接两分支得到128维 → LayerNorm → Linear64 → SiLU → Dropout → Linear1。共享预测头的MSE同时更新两个分支，构成内部融合。
- 对照：相同静态分支与预测头，序列64维输入固定为零；不训练纯GRU。静态分支和预测头在初始化时从同一权重快照复制，分别训练，记录参数量差异。
- 对照没有额外序列分支容量，因此阳性结果只支持“新增序列分支整套方案”的价值，不单独证明事件顺序因果价值。必要时在晋级后另行预注册顺序对照，不临时追加网格搜索。

每折保存三类预测：当前relative319 B001 trim1固定基线、静态网络对照、内部融合网络。
固定评估两种增量方案：
- baseline90 + static_control10
- baseline90 + joint_GRU10

组成部分在完整外部验证折分别L2单位化，权重固定90/10，不依据子窗口重新选择权重、中心化方式或epoch。对子窗口只做同一预测的筛选评分。缩放只依赖预测，不使用标签；它是历史融合既定约定，记录整折尺度。

第一阶段准入：
1. joint融合相对当前固定B001基线通过EXP-EVAL-001 v1四主指标门槛。
2. joint融合在四项主指标上均不低于static_control融合，且至少一项提高0.0005；确认增益不是只因新增静态网络。
3. 所有月度与删月证据照实记录，不以低标准差掩盖差的cosine。
4. 任一不通过：停止本方案的扩展，不运行第二阶段，不加seed、不全量训练、不准备新提交。
5. 通过仅表示值得确认，不表示泛化收益已经确定。两轮预算失败只否定这个低预算配置，不推出所有GRU融合无效。

预算：最多4次网络训练（2折×2网络），串行使用GPU。模型训练开始前把配置、特征列表、源码哈希与门槛写入run目录和实验记录。

## 第二阶段：严格前向折外embedding + 窗口特征树

仅第一阶段通过时启动，仍先seed42。不能拿第一阶段GRU对自身训练样本产生的隐藏向量训练树并称之为严格OOF。

低预算采用每个外部窗口一个前向内折：

| 外部验证 | GRU与其预处理fit月份 | 内部隔离月份 | 树训练行/折外表征月份 |
|---|---|---|---|
| 50–59 | 0–27 | 28–29 | 30–49 |
| 60–70（含62起隔离面板） | 0–37 | 38–39 | 40–59 |

流程：
1. 按第一阶段已冻结的内部融合架构，在GRU fit月份训练2轮；early stopping和参数选择不能看树训练折或外部验证标签。
2. 冻结全部网络和预处理。对树训练月份生成64维GRU最后有效隐藏状态；同一冻结编码器对外部验证生成64维表征。
3. GRU参数、目标尺度、输入预处理都不能使用对应表征行的标签或特征统计；只允许读取样本自身输入来transform和推理。
4. 树用319窗口特征+64表征，共383列，只fit表中“树训练行”的标签。对照树仅319列，但训练行、目标中心化、参数与seed完全相同。
5. XGBoost固定800棵、depth5、learning_rate0.03、min_child_weight100、lambda1、alpha0、subsample1、colsample0.8、hist、max_bin255、CUDA、n_jobs2，无外部验证早停。
6. 外部验证从未参与编码器或树的fit。冻结编码器对应的隐藏向量坐标保持一致，不把不同GRU的h_0列当成相同特征拼到一棵树。
7. 这是**单前向内折的严格折外表征**，不是所有0–49/0–59训练行都有OOF表征。早期编码器训练行不用于树训练；该样本损失是低预算和同一表征坐标的代价，必须报告。
8. 如以后扩展多个内折，每个编码器必须配自己的树，再在最终预测层融合。不同GRU隐藏维度可任意置换/旋转，不能简单把多折隐藏向量堆成一张表，或重训GRU后沿用旧树。

第二阶段预算：2个内折编码器、4个树（两外折×有无embedding），分批顺序执行。用同样90/10基线融合和四主面板评分；带embedding方案需过固定基线准入，并在四主分数上不低于无embedding对照、至少一项增益0.0005。

通过的具体路线才进入seed137完整配对确认，不同时扩展全部分支。seed137必须按同样门槛通过；不能把两seed压成一个有利的总分后忽略失败窗口。确认后再单独设计完整训练及冻结编码器/树的一致推理流程。

## 实现验收与运行纪律

- 每条embedding保存sample_id、month、encoder_id、encoder_train_end、预处理fit结束月份、源码/配置/权重哈希；标签放评分表，不拼进特征矩阵。
- 检查max encoder fit month < min embedding month，max tree fit month < min outer validation month，并验证内部两个月隔离。
- 检查所有join是一对一、缺失/重复ID直接报错；外部验证预测行与当前B001基线一致。
- 分批导出float32 embedding，保存元数据后再训练树；不用整个序列Tensor常驻内存。
- CPU总预算2线程；数值库、PyTorch、Arrow、XGBoost分别限制，只有一个计算任务活动。GPU优先，训练不降级到高负荷CPU。
- 不做模型smoke test。数据边界、对齐、padding与恢复一致性属于必要正确性检查。
- 每轮写训练日志和可恢复checkpoint；每折写预测、面板与结论，及时同步experiments，避免会话回滚丢状态。
- 长任务启动后使用Luna子代理只读监测日志与GPU状态；主任务继续处理实现审查和记录，不让监测代理启动第二个训练。
- 不调用Kaggle提交；当前两份0.134方案保留。完整训练和提交都不是本设计阶段的已完成事项。
