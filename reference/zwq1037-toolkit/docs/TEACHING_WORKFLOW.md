# 项目学习工作流

这套工作流解决两个问题：一是用 Kaggle 项目建立真实能力，二是用课外教材补齐项目容易遗漏的理论结构。不是先把书读完再比赛，也不是只写代码不理解。

## 文档之间的职责

- `PROJECT_PLAN.md` 只管理稳定的阶段路线。
- `LEARNING_PROGRESS.md` 是已验收、当前和下一课程状态的唯一事实来源。
- `LEARNING_RESOURCES.md` 管理资料定位与选择原则。
- 本文件只管理每一课如何执行。
- README 只提供稳定入口，不重复维护课程状态。

如果文件表述冲突，先以学习者实际代码和运行验收为证据修正 `LEARNING_PROGRESS.md`，再同步受到影响的路线文件；不能只靠聊天记忆选择课程。

## 一条完整课程链

```text
明确阶段能力
→ 检查前置知识和上课遗留问题
→ 选择本课真正相关的课外阅读
→ 带着 1～3 个问题阅读
→ 用人话讲清直觉
→ 学习一个最小例子
→ 学习者完成关键动手任务
→ Codex 只检查和运行
→ 学习者自行修正
→ 验收与口头复盘
→ 记录实验和学习进度
→ 决定下一课
```

## 1. 先确定本课要形成的能力

每一课开始前必须说明：

- 这一课在整个项目的哪个阶段；
- 它要解决哪个真实问题；
- 学完后学习者应该能独立完成或解释什么；
- 哪些内容明确不在本课学习，避免一次塞入太多概念。

课程不以“介绍了多少 API”为完成标准，而以是否形成可迁移能力为标准。

## 2. 课外阅读选择门

每次创建新课前，必须检查 `LEARNING_RESOURCES.md` 中的“已完成阅读记录”和本地教材。短期内读过且本课没有新增阅读深度的材料直接列为前置知识，不机械重复。若相隔较久、本课马上需要，或课前问题暴露出遗忘，可以安排间隔复习：先检查记忆，再决定只看摘要还是重读对应小节，并明确写成“复习”。只有与本课目标直接相关的内容才推荐，不为了形式同时推荐多本书。

讲义中的“配套阅读”必须说明六件事：

1. 资料名称和版本；
2. 准确的章、节标题和页码；
3. 课前读还是课后读；
4. 精读、理解直觉还是仅浏览；
5. 哪些公式、证明或代码暂时跳过；
6. 阅读后要回答的 1～3 个问题。

如果本课没有合适的外部阅读，必须明确说明原因，而不能默默省略。没有合适资料时，由讲义完整承担教学内容。

Python 语法以及 pandas、NumPy、scikit-learn、PyTorch、PyArrow 等库的 API 文档默认不布置给学习者阅读。Codex 负责查证官方资料，再把接口转化为当前课程中的人话解释、最小例子和具体用途。不能把阅读源文档当成函数教学的替代品。

若后期需要训练独立查文档能力，必须把它作为明确、低负担的小任务，并说明检索目标、阅读范围和验收问题；在此之前不要求学习者阅读 API reference。

## 3. 阅读不替代讲解

课外资料负责建立知识结构，Codex 仍要先用生活化语言回答：

```text
遇到了什么麻烦？
新概念为什么能解决？
用一个小数字例子会发生什么？
它回到当前比赛代码中是什么？
```

不能只丢出章节链接让学习者自己啃，也不能把整章内容复制进讲义。

## 4. 动手任务的选择

学习者亲手写的部分应至少满足一项：

- 建立关键直觉；
- 暴露常见误解；
- 训练以后还能复用的能力；
- 形成必要的代码肌肉记忆。

路径、固定数据、重复导入和已经掌握的模板可直接提供。每课主要引入 1～2 个新概念，并提供明确输入、输出和验收标准。

无需学习者填写的固定代码也必须按逻辑块添加简短的中英双语注释，尤其是路径定位、数据读取、排序、shape 检查、结果打印和验收判断。注释重点解释“这一段为什么需要”，不机械复述每个显而易见的符号。

结果判断题优先设计成真实决策：给出两个或更多可能合理、各有依据的方案，再混入一个大概率不合理的方案，让学习者选择并说明证据。不要总把题目写成只有一句固定答案的复述题；Codex 应在学习者选择后评价方案的收益、风险和验证方法。只有涉及数据泄漏、指标定义等确有唯一底线的内容，才使用明确的单一正确答案。

## 5. 验收与复盘

学习者说“完成”后，Codex 必须：

1. 读取原文件，不立即修改；
2. 运行并核对验收结果；
3. 先说明正确的核心流程；
4. 按影响解释错误原因和修正思路；
5. 让学习者自行修正；
6. 最终通过后，让学习者能用自己的话回答本课的 1～3 个核心问题。

代码通过但无法解释关键原因时，先用更小例子补直觉，不急着进入下一模型。

## 6. 资源如何贯穿整个项目

| 项目阶段 | 主要配套资料 | 资料承担的作用 |
|---|---|---|
| 数据和市场结构 | pandas/PyArrow 官方资料、Quant Wiki 选读 | 表结构、市场术语和数据直觉 |
| 时间验证和传统机器学习 | ISLP 指定小节 | 验证、过拟合、回归和树模型理论 |
| PyTorch 与 MLP | 《动手学深度学习》指定小节 | Tensor、训练循环、损失和优化 |
| 1D CNN | 《动手学深度学习》卷积章节 | 卷积核、通道、感受野和现代网络 |
| Transformer | 《动手学深度学习》注意力章节 | 自注意力、位置编码和 Encoder |
| 量化复盘 | Quant Wiki、ML for Algorithmic Trading 选读 | 回测、交易成本、风险和可交易性 |

准确章节不在这里一次写死，而是在每课开始时根据实际任务和本地版本定位。

## 7. 当前执行节奏

默认每一小课采用：

```text
课外阅读 10～25 分钟
讲义与提问 15～30 分钟
关键编码 20～60 分钟
运行、修正与复盘 10～30 分钟
```

章节过长时只选小节；理论较难时可以分为 A/B 两课，不为了赶进度跳过验证。
