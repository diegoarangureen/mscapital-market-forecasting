# 第5H课：从学习一批，到完整训练多轮

## 1. 这次解决什么问题

5G中，模型只看了第一批两个样本，更新了一次参数。就像做练习册时只做了第一页，还不能算学完一遍。

现在我们要做两件事：

1. 把全部训练样本分批学完，再重复几遍；
2. 给每一遍记一个有明确含义的平均损失。

本课仍用小数据、同一个MLP和SGD，不换模型、不加真实大文件、不调参。你写循环和损失统计；已经验收的单batch训练代码直接复用。

## 3. batch、step、epoch不是同一件事

把训练集想成一本练习册：

- batch：这次拿出来一起做的几道题。
- step：根据这一批的错误，调整一次参数。
- epoch：把训练集完整走过一遍。

例如有7个样本，batch size为3，并且不丢弃尾批：

```text
第1轮：3个样本 → 更新；3个样本 → 更新；1个样本 → 更新
第2轮：再把7个样本分批处理，继续更新已有参数
```

一轮有3批，本课每批更新一次，所以一轮有3个step。训练4轮就是12次更新。

第二轮不是重新造一个模型。它继续使用第一轮学到的权重，就像第二遍做题时不需要把第一遍学的东西忘掉。

因此，模型和优化器都创建在epoch循环外；每批的`zero_grad()`只清梯度，不清权重。

## 4. 双层循环如何工作

### `range()`：让一段代码重复指定次数

这是Python内置功能，不用import。基本语法`range(stop)`接收整数，返回一个range对象，可以交给for逐个取整数。

`range(3)`依次给出`0、1、2`，不包括3。它不是Tensor，没有这里要讨论的shape。

```python
# 重复两轮；内部编号从0开始，显示时加1。
# Repeat two rounds; add one only for display.
for round_index in range(2):
    print("round =", round_index + 1)
    for question in ["题目甲", "题目乙"]:
        print(question)
```

输出顺序是第1轮、甲、乙，然后第2轮、甲、乙。

在本项目里，外层换成epoch，内层换成DataLoader。`for batch_features, batch_targets in data_loader:`会自动取下一批并解包，不再需要你手动写`iter()`和`next()`。

每次重新进入这个DataLoader循环，都会开始新一遍遍历。不要把5G中已经用完的`batch_iterator`放在外面反复遍历；迭代器耗尽后不会自己从头开始。

本课`shuffle=False`只是为了方便检查固定批次。以后训练集内部可以shuffle，但仍不能混入验证月份。

### 缩进决定“多久做一次”

```text
创建模型、优化器                  整次训练只做一次
外层epoch循环：
    清空本轮统计                 每轮做一次
    内层batch循环：
        清梯度、前向、loss、反向、step    每批做一次
        累计本批统计                    每批做一次
    计算并打印本轮平均损失         每轮做一次
```

注意：统计量不能在每批开头清零，否则最后只剩尾批；也不能只在全部训练开始前清零，否则打印的会是多轮混在一起的平均。

## 5. 提供的`model.train()`不是“一键训练”

它是PyTorch模型的方法，基本语法为`model.train()`，等价于传入布尔参数`mode=True`。返回模型自身，一般不用接住返回值。

```python
from torch import nn

# 创建一个最小模型，并设置训练模式。
# Create a minimal model and set training mode.
small_model = nn.Linear(2, 1)
small_model.train()
```

这段代码没有提供数据，没有计算loss，更没有更新权重。它只是切换模型模式。

当前Linear和ReLU在训练/验证模式下计算方式一样；以后某些层会区分两种模式，因此我们现在养成在训练开始时调用它的习惯。它不会替你执行`backward()`或`step()`，也不会把数据移到GPU。验证模式下一课再讲。

## 6. 为什么不能把每批loss直接平均

先脱离神经网络：第一组有3个学生，平均错2题；第二组只有1个学生，错8题。

若算`(2+8)/2=5`，就把“3个人的一组”和“1个人的一组”当成同样重了。

正确的每人平均错题数是：

$$
\frac{2\times3+8\times1}{3+1}=3.5
$$

先把每组平均值乘人数，恢复总量；合计后再除以总人数。

本课也是这样。默认`nn.MSELoss()`把所有输出元素的平方误差取平均；当前每个样本恰好只有一个输出，shape是`(batch_size, 1)`，因此它就是这一批的每样本平均平方误差。

记第$b$批平均损失为$L_b$，实际样本数为$n_b$，共有$B$批：

$$
L_{\text{epoch}}=\frac{\sum_{b=1}^{B}L_b n_b}{\sum_{b=1}^{B}n_b}
$$

人话：每批平均loss乘这一批实际人数，加起来，再除以本轮看过的总人数。

如果所有批人数一样，直接平均批loss恰好也对；但尾批经常不满，所以写成按人数加权更稳妥。这里只讨论每样本一个目标的普通MSE，不把这个公式直接套到有mask或不同有效长度的序列loss上。

### 需要用到的两个旧工具

`batch_features.shape[0]`：Tensor的shape属性给出各维大小，`[0]`取第一维，即本批实际行数，返回整数。例：shape为`(1, 3)`时结果为1，不能因为配置了batch size 2就硬写2。

`loss.item()`：Tensor方法，无需参数，把只有一个元素的Tensor转换成Python数值；本课返回float。例：`torch.tensor(0.25).item()`得到`0.25`。记录统计用数值，反向传播仍用原来的loss Tensor。多个元素的Tensor不能直接item。

用于记账的最小例子：

```python
# 将一组的平均值还原成总量，再加入已有累计值。
# Recover a group total from its mean and add it to the running total.
total_mistakes = 0.0
group_mean = 2.0
group_size = 3
total_mistakes = total_mistakes + group_mean * group_size
```

本课保留完整赋值写法。以后看到`total_mistakes += ...`，在这里可理解为相同的累加操作。

## 7. 我们记录的是“边学边记的loss”

第一批算loss时用的是初始权重；第二批算loss时，模型已经更新过一次。因此本轮日志汇总的是不同训练时刻的损失，不是轮末固定模型重新预测整个训练集的损失。

本课每批只做一次前向计算，不再像5G那样为了演示更新前后差异而额外前向一次。`step()`后读取旧`loss.item()`仍然是在记录该批更新前的损失，数值不会自动改变。

它能帮助我们发现：训练是否在运行，损失是否总体变小，是否出现nan或爆炸。但它不能证明验证集更好，更不能直接与LightGBM的余弦分数比较。

下一课会固定每轮训练结束时的模型，在验证集上只预测不更新，再计算全验证集的cosine。
