# 第6B课：把真实market整理成CNN序列

## 1. 本课要解决的真实麻烦

6A中的每个样本都有8个等间隔时刻，所以可以直接组成`(batch, channels, time)`。真实market不是这样整齐：

- 完整特征表显示，1,257,637个样本的行数从1到212不等，中位数189；
- 小样本相邻记录通常约3秒，但并非严格落在统一格点；
- 样本4甚至有相邻两行只差约0.193秒，把`seconds/3`四舍五入会让两行撞进同一个格子；
- `transaction_avgprice`在无成交时可能是`NaN`；
- 神经网络的一个batch必须能堆成统一shape。

因此，本课不训练CNN，而是建立第一版**序列输入契约**：同一种输入shape中的每个位置和通道到底代表什么。

学完后你应该能独立解释并实现：

1. 截断（truncation）与左侧补齐（left padding）；
2. 有效位置标记`row_mask`；
3. 为什么标准化统计量只能从训练期真实行学习。

本课不做全量缓存、不训练模型、不比较分数。路径、统计量计算、数值通道写入和Tensor转换已经提供；你只填写排序/截断、右对齐起点和mask三组核心代码。

### 1.1 先不看代码：一条样本到底会经历什么？

先把这一课当作“整理行李箱”，不要急着想CNN。

假设样本1原本有107行market记录。每一行都是一个观测时刻，包含倒计时、价格、盘口量和成交信息。我们的目标不是把107行压缩成均值，而是把这107行逐行保留下来，放进一个固定有200个位置的容器。

第一步，按倒计时从大到小排列：

```text
595.676秒，592.684秒，589.671秒，……，4.697秒，1.708秒
      较早                                           最近
```

因为倒计时越小越靠近预测时点，所以排序后最重要的“最近记录”自然位于最右边。

第二步，建立一个200行、14列的全0容器：

```text
sequence_data.shape = (200, 14)
```

这里：

- 200行不是200个样本，而是**一个样本的200个序列位置**；
- 14列不是14个时间点，而是**每个位置保存的14个通道**。

第三步，计算107条真实记录应该从哪里开始写：

$$
200-107=93
$$

于是这个样本变成：

```text
序列位置： 0 ........ 92 | 93  94  95 ........ 199
内容：     padding 93行 | 真实market记录 107行
时间方向：               | 较早 .......... 最近
row_mask： 0 ........  0 |  1   1   1 ........ 1
```

注意两个容易混淆的“93”：

- 原样本有107行；
- 因为目标是200行，所以需要补93行；
- 索引从0开始，因此真实数据恰好从索引93写入。

第四步，每条真实记录不再只是一个数，而是写入这一行的14个通道。padding行保持全0；真实行的`row_mask`写为1。

第五步，5个样本都整理完后，NumPy数组是：

```text
(5, 200, 14) = (样本, 序列位置, 通道)
```

最后复用6A的`permute(0, 2, 1)`，变成Conv1d需要的：

```text
(5, 14, 200) = (样本, 通道, 序列位置)
```

所以本课全部工作的本质是：

```text
每个sample_id下面长短不同的多行DataFrame
                         ↓
每个sample_id一个固定shape的二维数组(200, 14)
                         ↓
多个样本堆成(batch, 200, 14)
                         ↓ permute
CNN输入(batch, 14, 200)
```

我们没有生成新的训练样本，也没有把一行market当成一个标签。仍然是“一整段market序列对应一个target”。

### 1.2 为什么不能直接让DataLoader处理107行和199行？

一个普通batch需要形成规则的长方体Tensor。例如两个样本若分别为：

```text
样本A：(199, 14)
样本B：(107, 14)
```

它们不能直接堆成`(2, ?, 14)`，因为问号不可能同时等于199和107。padding把它们都变成`(200,14)`，才可以堆成`(2,200,14)`。

padding不是为了假装那些时刻真的有行情，而是为了满足批量计算的shape要求；`row_mask`负责保留“这里其实是空的”这一事实。

## 3. 为什么暂时不强行建立“每3秒一个格子”？

一种看起来很自然的写法是：

```python
slot = round(seconds_before_predict / 3)
```

它暗含三个未经证明的假设：

1. 所有样本使用相同的时间相位；
2. 每个3秒格子最多一行；
3. 偏离格点只是足够小的随机误差。

小样本已经推翻第2条：样本4有两行约为221.778秒和221.971秒，它们可能被映射到同一个整数格。此时我们必须额外决定保留哪行、平均两行还是增加一个位置；任何选择都会改变数据。

所以第一版采用更保守的**观测序列（observation sequence）**：按真实倒计时排序，让卷积核查看连续记录，同时把倒计时本身作为输入通道。它不是严格等间隔时间网格，我们必须如实描述：

> 核宽3表示连续3条保留下来的market记录，不保证恰好覆盖9秒。

这比假装数据严格等间隔更可信。后面可以把严格重采样作为独立实验，但必须明确碰撞、插值和空格规则。

## 4. 第一版序列怎样对齐？

固定：

```python
MAX_STEPS = 200
```

每个样本先按`seconds_before_predict`从大到小排序：

```text
倒计时大：离预测较远，放左边
倒计时小：离预测较近，放右边
```

### 样本少于200行：左侧补0

如果只有4条观测，目标长度为6：

```text
位置：       0    1    2    3    4    5
数据：      PAD  PAD  较早  ...       最近
row_mask：   0    0    1    1    1    1
```

真实数据从这个位置开始：

$$
start=MAX\_STEPS-observed\_count
$$

数字例子中：

$$
start=6-4=2
$$

所以真实行写进`sequence[2:]`，前两个位置保留为0。

为什么靠右？因为模型预测的是某个预测时点之后的目标，我们优先让每个样本“最靠近预测的观测”对齐到同一个末端位置。

### 样本多于200行：保留最近200行

排序后最靠近预测的记录位于末尾，因此保留最后200行。少量最远端记录会被丢弃。这是建模选择，不是假装原始数据只有200行。

完整统计显示最长样本212行；第一版最多丢弃最远端12行。是否值得改成212或别的长度，需要通过资源和验证实验判断，不能只看一个样本决定。

## 5. `row_mask`解决什么问题？

### 先说人话：`row_mask`就是点名册

我们为了让所有样本都有200个位置，会给短样本补很多行0。但这些补出来的行只是“空座位”。`row_mask`就像点名册：

```text
row_mask=1：这个座位上真的有一条market记录
row_mask=0：这是为了凑够200行而放的空座位
```

它不描述有没有成交，只描述“这一整行记录是否真实存在”。真实market行即使没有成交，也仍然记录了盘口价格和数量，所以它应该是`row_mask=1`。

padding位置必须填入有限数，否则无法形成Tensor。但数值0可能也是标准化后的正常值，所以模型仅看数值无法区分：

```text
这个0是补出来的空位置
还是某特征恰好等于训练均值？
```

我们增加一个通道：

```text
row_mask = 0：补齐位置，没有真实market行
row_mask = 1：真实观测行
```

它和`has_transactions`不相同：

| 状态 | row_mask | has_transactions |
|---|---:|---:|
| padding位置 | 0 | 0 |
| 真实行，但没有成交 | 1 | 0 |
| 真实行，而且有成交 | 1 | 1 |

因此不能只保留`has_transactions`来代替`row_mask`。

用一个更具体的三行例子：

```text
位置       transaction_count   has_transactions   row_mask
padding            0                  0               0
真实无成交行        0                  0               1
真实有成交行        5                  1               1
```

前两行的`has_transactions`都是0，但含义完全不同：第一行根本不存在真实记录，第二行存在记录、只是当时没有成交。只有再看`row_mask`才能区分它们。

本课只把mask作为输入通道。固定的`AdaptiveAvgPool1d(1)`仍会把padding位置纳入平均；6C建立模型时需要使用mask-aware pooling，不能以为“给模型一列mask”就自动让所有层忽略padding。

### 把mask输给CNN，和强制CNN忽略padding，是两件事

`row_mask=0`本身是普通的有限数值，输入CNN不会产生`NaN`，也不会让程序报错。它的作用是给模型一条信息：“这个位置是padding。”但普通`Conv1d`不会看到0就自动跳过该位置；对它来说，mask只是14个输入通道中的一个。

即使padding位置的所有输入都是0，卷积输出也不一定是0：

1. 卷积层通常有偏置，输入全0时仍可能输出偏置；
2. 核宽3的窗口可能同时盖住padding位置和旁边的真实位置；
3. 经过多层卷积后，边界附近的信息还会继续传播。

所以“把mask作为输入”只是让CNN**有机会学习**如何区分padding；“mask-aware pooling”则是在计算规则中**明确保证**padding不进入最终平均。

假设某条隐藏响应有6个位置，只有后三个是真实位置：

```text
hidden response = [1, 1, 1, 2, 4, 6]
row_mask       = [0, 0, 0, 1, 1, 1]
```

普通平均池化会计算：

$$
(1+1+1+2+4+6)/6=2.5
$$

其中前三个响应来自padding区域，却参与了结果。masked mean先将响应乘mask，再只除以真实位置数：

$$
\frac{1\times0+1\times0+1\times0+2\times1+4\times1+6\times1}{0+0+0+1+1+1}=4
$$

形式上，对每个样本和隐藏通道：

$$
pooled=\frac{\sum_t h_t m_t}{\sum_t m_t}
$$

$h_t$是卷积产生的隐藏响应，$m_t$是`row_mask`。这样真实记录少的样本不会因为左侧padding多，就被普通平均额外稀释。

6C中会把输入和mask分开使用：输入通道仍可包含mask，帮助卷积识别边界；池化时再用同一mask明确排除无效位置。必要时还会在卷积层之间把无效位置重新清零，不能只依赖模型自己猜。当前6B只负责正确构造并保存这个事实，还没有执行池化。

这里还有两种不同的“补零”，不要混淆：

- **序列padding**：把107行样本补成200个位置，由`row_mask`标记；
- **`Conv1d(padding=1)`**：为了让核宽3卷积前后长度保持不变，在序列边界临时补零。

前者解决不同样本长度，后者解决卷积输出长度；它们不是同一件事。

## 6. 第一版14个输入通道

### 先说人话：每个时刻带一个有14格的小表单

200表示最多保留200个观测位置；14表示每个位置要记录14项信息。可以想象每条真实market记录都填写一张14格表单，然后把最多200张表单按时间排好。

```text
一个样本
├── 位置0：14项信息
├── 位置1：14项信息
├── ……
└── 位置199：14项信息
```

所以`(200,14)`不是200个样本，也不是14个预测目标，而是“一个样本最多200条记录，每条记录14项信息”。

每个真实位置保存：

1. 11个原始数值字段：平均成交价、成交量/次数、两档买卖价格与数量；
2. `seconds_before_predict / 600`：保留真实倒计时的大致位置；
3. `has_transactions`：该真实记录中是否发生过成交；
4. `row_mask`：这个序列位置是否真的存在一行market数据。

总计：

$$
11+1+1+1=14个通道
$$

把“一个真实时刻的一行”横着展开，可以理解成：

```text
[11个标准化数值 | 倒计时/600 | 是否有成交 | 这行是否真实]
```

例如这里只写示意值：

```text
[0.20, -0.35, 1.10, ..., 0.48 | 0.25 | 1 | 1]
```

- 前11个数描述这个时刻的市场数值；
- `0.25`表示距离预测大约$0.25\times600=150$秒；
- 第一个1表示当时有成交；
- 最后一个1表示这个序列位置来自真实market行。

一个padding位置则是：

```text
[0, 0, 0, ..., 0 | 0 | 0 | 0]
```

最后的`row_mask=0`告诉后续模型：这一整行只是为了凑shape。

输出Tensor：

```text
(5, 14, 200)
 ↑   ↑    ↑
样本 通道 观测位置
```

这只是第一版输入合同，不表示14一定最佳。`sample_id`只负责分组，`target`是答案，都不能作为CNN输入。

## 7. 标准化与缺失：先对真实行学习，再补0

### 先说人话：先把不同单位换成差不多的刻度

价格可能在1附近，成交量可能是几万甚至几十万。直接交给神经网络，就像把“1米”和“100000毫米”放在一起比较：后一个数字巨大，不代表它一定更重要，只是单位不同。

标准化就是给每个数值字段分别换一把尺子，让“比该字段平常水平高多少或低多少”使用相近刻度。它不会把成交量和价格混成同一个字段，也不会改变时间顺序。

价格约为1，成交量可能很大。直接混合这些尺度会让神经网络难训练，所以11个数值通道继续标准化：

$$
x_{scaled}=\frac{x-\mu_{train}}{\sigma_{train}}
$$

这里：

- $x$是一个原始数值；
- $\mu_{train}$只由训练期真实行计算；
- $\sigma_{train}$只由训练期真实行计算；
- 缺失值不参与该列均值和标准差；
- 标准化后仍然缺失的位置填0，同时保留`has_transactions`说明成交状态。

顺序非常重要：

```text
训练期真实行学习均值/标准差
→ 用同一统计量变换训练和验证
→ 缺失数值填成标准化空间的0
→ 把样本写进固定长度数组
→ padding区域保持0并用row_mask标出
```

### 7.1 为什么要先标准化，再让padding保持0？

先看一个只有成交量的极小例子。假设训练期两条真实记录是：

```text
成交量：[10, 12]
```

真实均值是：

$$
\mu_{train}=(10+12)/2=11
$$

如果为了凑4行先补两个0，再计算均值，就会错误地得到：

$$
(0+0+10+12)/4=5.5
$$

但前两个0是我们人工制造的，不是市场成交量。让它们参与统计，相当于谎称市场里真的出现了两条成交量为0的观测。

正确顺序是：

1. 只用真实训练行得到均值11和标准差；
2. 把真实值10、12变换到标准化空间；
3. 最后才把它们放入全0容器；
4. 用`row_mask`说明哪些0是padding。

### 7.2 缺失值填0为什么不等于“原始价格为0”？

`transaction_avgprice`在没有成交时可能为`NaN`。它先经过：

$$
x_{scaled}=\frac{x-\mu_{train}}{\sigma_{train}}
$$

正常情况下，标准化空间中的0代表“训练均值附近”，并不代表原始价格0。对仍为`NaN`的位置，我们在这个标准化空间填0，同时保留`has_transactions=0`。

因此模型看到的是：

```text
数值通道 = 一个有限的中性占位值
has_transactions = 0，说明平均成交价为何不存在
row_mask = 1，说明这一整条market记录是真实存在的
```

这三个信息一起看，才不会把“无成交”误认为“整行不存在”。

### 7.3 为什么验证数据不能参与均值和标准差？

假设训练期成交量均值为10，未来验证期均值变成20。如果合起来算出15，再去处理训练数据，训练阶段就提前利用了未来市场整体水平。

即使没有读取`target`，这仍然是未来信息进入训练流程。因此完整实验必须是：

```text
月份0～59：计算均值和标准差
月份0～59：用它们变换
月份60～70：只使用同一统计量变换，不更新
```

不能先padding再计算均值。否则样本1要补93行0，这些人为0会被当成真实市场数据，扭曲统计量。也不能用月份60～70更新均值或标准差，否则发生验证泄漏。

本课的5个样本全部来自月份0，不能构成正式时间验证。练习仅用ID 0～3演示“学习统计量”，再把相同统计量用于ID 4；这叫接口演示，不把ID 4分数解释成验证成绩。全量阶段严格使用月份0～59学习统计量，月份60～70只变换。

## 8. 本课新语法和接口

### 8.1 `DataFrame.tail(n)`

它是pandas DataFrame的方法，项目已有`import pandas as pd`。输入参数`n`是整数，返回最后最多`n`行组成的新DataFrame，列不变，并保持原来的行顺序。

```python
import pandas as pd

example = pd.DataFrame({"value": [10, 20, 30, 40]})
last_two = example.tail(2)
print(last_two)
# value为30、40的两行
```

当前比赛中，数据先按倒计时从大到小排列，末尾更靠近预测，因此`.tail(200)`保留最近200条观测。常见错误是没有先排序就调用`tail()`，那只能取得当前文件顺序的末尾，无法保证时间意义。

### 8.2 `np.zeros(shape, dtype)`

这是NumPy函数，需要`import numpy as np`。`shape`是整数元组，返回指定shape的`np.ndarray`；`dtype=np.float32`控制数值类型。

```python
empty_sequence = np.zeros((6, 3), dtype=np.float32)
```

得到6行3列的零数组。当前比赛先建立`(200,14)`，再把真实行写到右侧；返回仍是二维数组。

### 8.3 切片赋值`array[start:, column] = values`

它不是函数，也无需import：方括号选择数组区域，等号把右侧值写进去。

```python
example = np.zeros((5, 2), dtype=np.float32)
example[3:, 1] = 1.0
```

- `3:`：第0轴选择索引3到结尾；
- `1`：第1轴只选择第1列；
- 左边区域shape是`(2,)`，标量`1.0`会写入这两个位置。

当前比赛用它把真实位置的`row_mask`设为1。常见错误是用`sequence[:observed_count]`，这会把短样本靠左对齐，与“最近记录在末端”规则冲突。

### 8.4 本课固定代码中的接口

这些不是核心填空，但第一次见到时要知道职责：

- `DataFrame.mean()`：逐列计算均值，默认忽略`NaN`，返回以列名为索引的`Series`。
- `DataFrame.std(ddof=0)`：逐列计算总体标准差，返回`Series`；`ddof=0`表示除以$n$，与之后的固定标准化合同一致。
- `DataFrame.fillna(0.0)`：返回把缺失位置替换成0的DataFrame；这里在标准化之后调用，不覆盖原始文件。
- `DataFrame.to_numpy(dtype=np.float32)`：返回只包含数值的二维NumPy数组，shape为`(行数, 列数)`。
- `np.isfinite(array)`：逐元素判断是否为有限数，返回相同shape的布尔数组；再调用`.all()`得到一个布尔值。
- `torch.from_numpy(array)`：从NumPy数组建立Tensor，通常共享底层内存；本课转换后不再修改原数组。

pandas在`DataFrame - Series`和`DataFrame / Series`时会按相同列名对齐，所以统计量不依赖列的偶然位置。注意：`fillna(0)`不是“原始平均成交价等于0”，它表示该数值在标准化空间采用中性安全值，同时由状态通道保存缺失含义。
