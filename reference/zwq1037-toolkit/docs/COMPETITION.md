# 比赛信息卡

## 我们目前知道什么

- 任务：根据市场、委托和成交信息预测未来收益相关目标。
- 训练时间：月份编号约为 `0–70`。
- 测试时间：月份编号约为 `71–108`。
- 评价指标：Cosine Similarity（余弦相似度），越大越好。
- 主要数据流：
  - `market.feather`：预测时点前约 600 秒的等间隔市场序列。
  - `order.feather`：预测时点前约 60 秒的委托数据。
  - `transaction.feather`：预测时点前约 60 秒的成交数据。
  - `label.feather`：训练标签。
- 原始数据总量约 `9.95 GB`，其中训练和测试的 market 数据最大。
- 主办方没有公开目标构造的全部细节。

## 最重要的实验规则

测试月份全部晚于训练月份，所以不能像上一场比赛那样随机打乱后做 K-fold。验证集必须来自更晚的月份：用过去训练、用未来验证。

```text
较早月份                         较晚月份
[       train       ] [ validation ] [ test ]
```

任何使用完整时间范围计算的统计量，都可能把未来信息带回过去。预处理器、特征统计和模型都只能在当前训练区间上学习。

## 第一阶段的数据范围

我们不会一开始同时处理三张超大事件表。顺序是：

1. 先读取 `label` 和一小部分 `market`。
2. 用少量月份、少量样本跑通流程。
3. 建立 LightGBM 聚合特征基线。
4. 再把 `market` 保留为序列，训练 1D CNN。
5. 最后才考虑 Transformer 以及加入 order/transaction。

## 需要通过数据实际确认的问题

- 一个标签行由哪些键与 market/order/transaction 对齐？
- 每个样本实际有多少个时间步和特征？
- 是否存在缺失、重复或长度不一致的序列？
- 标签分布、月份分布和资产分布如何？
- 官方提交文件要求哪些列？

这些问题将在下载样本后由学习者亲手检查，而不是现在凭猜测写死。
