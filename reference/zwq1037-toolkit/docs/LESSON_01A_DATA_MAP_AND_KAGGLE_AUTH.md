## 1. 为什么不是一张 `train.csv`？

上一场比赛中，一行基本就是一个用户，特征和标签都能整理成同一张二维表。

金融市场在一个预测时点之前会发生许多事件：价格不断变化、交易者不断挂单和撤单、买卖不断成交。因此一个预测样本通常对应一段历史，而不是只对应一行：

```text
一个预测样本
├── 一行标签：将来的变化是什么
├── 多行 market：预测前一段时间的等间隔市场状态
├── 多行 order：预测前发生的委托事件
└── 多行 transaction：预测前发生的成交事件
```

这也是后面能够使用 1D CNN 和 Transformer 的原因：模型看到的是按时间排列的序列。

## 2. 四类文件的角色

### `label.feather`

训练阶段的答案表。每行对应一个需要预测的样本，并含有用于对齐其他表的标识信息。具体列名必须等文件下载后实际检查，当前不凭猜测写死。

### `market.feather`

等间隔记录的市场状态，覆盖预测时点前较长的一段窗口。它最接近规则整齐的时间序列，是我们最先用于 CNN/Transformer 的数据流。

### `order.feather`

委托事件记录，例如市场参与者提交或更新买卖意愿。事件发生时间不一定等间隔。

### `transaction.feather`

实际成交事件记录。挂单不一定成交，所以它和 order 表表达的信息不同。

## 3. 为什么先下载 `label`？

完整数据约 10 GB，大表包含上亿行；但标签表相对较小。先看标签可以确认：

- 样本总数；
- 目标列；
- 月份范围；
- 与其他表对齐的键；
- 缺失情况。

这些信息决定后面应该如何抽样和验证。直接下载并读取最大表只会增加等待和内存风险。

## 4. Kaggle 网页登录与本地认证

浏览器保存的是网页会话；PyCharm 里的程序是另一个客户端。Kaggle 不会自动把网页凭证交给本地 Python，所以本地工具第一次访问 API 时需要单独授权。

我们使用 OAuth 登录：

```powershell
D:\anaconda\envs\pytorch\Scripts\kaggle.exe auth login
```

拆开理解：

- 前半段是当前 Conda 环境中的 Kaggle 程序。
- `auth` 表示账户认证功能。
- `login` 表示开始登录。

命令会给出浏览器授权流程。登录和确认由学习者本人完成；不要把访问令牌、密码或认证文件内容发给 Codex。

## 5. 只下载单个文件的命令结构

认证完成后我们将使用类似结构：

```text
kaggle competitions download 比赛名 --file 文件名 --path 保存目录
```

其中：

- `competitions download`：下载比赛文件。
- `--file`：指定一个文件；省略它会下载全部文件。
- `--path`：指定保存目录。

暂时不要自己猜文件名执行下载。我们先让工具列出官方文件路径，再选择标签文件。
